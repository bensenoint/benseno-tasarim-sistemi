# P3.3c — Haftalık GM Brifingi (Tasarım)

**Tarih:** 2026-07-07
**Faz:** P3.3 Proaktif zeka → alt-faz **c** (sentez). **Dayanır:** P3.3a (sinyal motoru) + P3.3b (tahmin). P3.3'ün son alt-fazı.

---

## Amaç

P3.3a+b'nin ürettiği tüm sinyalleri + finans durumunu haftada bir **Opus** ile sentezleyip yöneticilere anlatısal "hafta-önü" brifingi göndermek. Ody "sorulunca cevaplayan"dan "haftalık kendiliğinden brifing veren"e döner (fırsat haritası Y6).

## Kapsam

**Dahil:**
- Yeni script `scripts/firma-brifing.js` + wrapper `scripts/run-firma-brifing.sh`.
- `scheduler.js`: Pazartesi 08:00 cron.
- Saf olgu-toplama (`brifingOlgulari`) + Opus sentezi + deterministik fallback.
- Dinamik yönetici + GM'e DM (P3.3a `tip_firma_sinyal` toggle + sessiz-saat YOK — planlı haftalık rapor).

**Kapsam dışı:** Cuma retrospektifi (YAGNI, tek brifing); yeni sinyal tipi (mevcutları sentezler); UI (Slack-only).

**Migration yok / yeni tablo yok.**

## Erişim / güvenlik

- Alıcı: dinamik `rol='yonetici'` VEYA `yetki='yonetici'` + GORKEM (P3.3a `yoneticiMi`), DM.
- `notify_prefs.tip_firma_sinyal === false` → o yönetici almaz (mevcut toggle yeniden kullanılır).
- Finans (kâr/marj/tahsilat) içerir → yalnız yöneticiye (P3.1 kuralı; kişilere gitmez).
- Opus'a giden olgular `commentary()` guard'ıyla aynı korunur: "yalnız verilen olgulara dayan, tarih/proje-türü/müşteri UYDURMA."
- SLACK/ANTHROPIC token'ları asla loglanmaz.

## Mimari

Yeni script `scripts/firma-brifing.js`, `firma-sinyal.js` ve `rapor-gunluk.js` desenlerini izler. `scripts/` tüm repo'ya eriştiği için `require('../dashboard/app/calc')` güvenli (scheduler imajı `COPY . .` → dashboard/ dahil). **server/ içine taşınmaz.**

Akış (`main`):
1. `fetchEmbedded()` → snapshot.
2. `brifingOlgulari(d, now)` (saf) → `{ sinyaller, finans, kapasitePct, gecikenSayi, ozet }`.
3. `ANTHROPIC_API_KEY` varsa Opus çağrısı (`claude-opus-4-7`) → anlatısal metin; yoksa/başarısızsa **deterministik fallback** (`fallbackMetin(olgular)`).
4. Dinamik yönetici + GM listesi (`yoneticiMi`, P3.3a'dan import) → her birine `tip_firma_sinyal` açıksa `post(tok, uid, metin)`.

Cron (`scheduler.js`, NOTIFY_V2 bloğu):
```js
cron.schedule('0 8 * * 1', () => run('run-firma-brifing.sh'), opts); // Pazartesi 08:00
```

### Bileşenler
- **`brifingOlgulari(d, now)`** (firma-brifing.js, saf, test edilebilir): `sinyalleriHesapla`'yı (firma-sinyal.js'ten import) çağırır + `bnsFinansOzet` (calc) + kapasite. `sinyalleriHesapla` async (risk_seviye DB sorgusu içerir) — DRY modda riskMap boş; brifing canlı çalıştığından DB erişir.
- **`fallbackMetin(olgular)`** (saf): Opus yoksa olguları düz Türkçe listeye çevirir.
- **Opus çağrısı**: model `claude-opus-4-7`, max_tokens ~800, system = brifing rolü + `commentary` guard metni, user = olgular JSON.

## Veri akışı

`sinyalleriHesapla` P3.3b sonrası tüm sinyalleri döndürür (kapasite, geciken, marka-risk, kişi-kalite, gecikme öngörüsü, burnout). Brifing bunları + finans özetini olgu olarak Opus'a verir. Opus hafta-önü anlatısı üretir. `sinyalleriHesapla`'nın DB sorgusu (risk_seviye) `--dry` değilken çalışır.

## Hata yönetimi

- `SLACK_BOT_TOKEN` yok → log + çık (firma-sinyal deseni).
- `ANTHROPIC_API_KEY` yok VEYA Opus HTTP hatası → `fallbackMetin` ile deterministik brifing yine DM edilir (brifing hiç boş kalmaz).
- `fetchEmbedded` hatası → hata koduyla çık; scheduler hata DM'i atar.
- Bir alıcıya DM hatası yutulur, diğerlerine devam.

## Test

`scripts/formula-test.js` veya script-içi (firma-brifing.js `module.exports`):
- `fallbackMetin`: verilen olgularla beklenen düz metin bloklarını (sinyal sayısı, finans satırları) içerir.
- `brifingOlgulari` wiring: sentetik `d` ile sinyal sayısı + finans alanları doğru (Opus çağrılmadan; `--dry` yolu).
- Opus çağrısı test edilmez (dış servis). Fallback yolu ve olgu-toplama test edilir.
- Manuel: `node scripts/firma-brifing.js --dry` → olgular + hedef liste; hata yok.
