# P3.3b — Tahmin Katmanı (Tasarım)

**Tarih:** 2026-07-07
**Faz:** P3.3 Proaktif zeka → alt-faz **b** (tahmin)
**Dayanır:** P3.3a (firma-sinyal push motoru). **Sonraki:** P3.3c (haftalık GM brifingi).

---

## Amaç

Sistemi reaktiften öngörüye taşımak: "bu iş yetişmeyebilir" (gecikme öngörüsü) ve "X bu hafta boğulacak" (burnout projeksiyonu) sinyallerini erkenden üretmek; ayrıca kişi-performans metrik hesaplama katmanını kurmak (P3.4'ün temeli).

## Kritik kısıt (canlı veri bulgusu)

`tahmini_sure_h` alanı **%0 dolu** (100 aktif + 123 tamamlanan işte hiç girilmemiş). Bu yüzden **hiçbir öngörü per-iş tahmine dayanamaz** — hepsi gözlemlenen veriden türetilir (döngü süreleri, revize, deadline yoğunluğu, kapasite).

## Kapsam

**Dahil:**
- calc.js: 3 metrik/öngörü fonksiyon ailesi + baseline yardımcısı + 2 sinyal sarmalayıcı (saf, CI-testli).
- firma-sinyal.js: 2 yeni sinyal tipi (`gecikme_ongoru`, `burnout`) — mevcut P3.3a motoruna (dedup/sessiz-saat/toggle) bağlanır.
- Dashboard: at-risk aktif brief'lerde "⏳ öngörülen gecikme" rozeti (atanan + yönetici görür).

**Kapsam dışı:**
- Kişi-performans metriklerinin ekran gösterimi → P3.4 (bu fazda yalnız calc katmanı).
- LLM sentezli haftalık brifing → P3.3c.
- `tahmini_sure_h` giriş akışı → YAGNI; gözlemlenen veriyle çalışıyoruz.

**Migration yok:** yeni sinyaller mevcut `notifications` + `tip_firma_sinyal` toggle'ını (P3.3a) kullanır.

## Erişim / güvenlik

- Sinyaller (gecikme + burnout): yalnız yöneticiler + GM (P3.3a `yoneticiMi` + `tip_firma_sinyal`).
- Dashboard "öngörülen gecikme" rozeti: **atanan + yönetici** görür (kişi kendi işinin riskini görebilmeli). Finans/puan içermez → hassas değil.
- Burnout kişi-bazlı: sinyal yalnız yöneticiye (kişinin kendisine değil).

## Fonksiyon tanımları (calc.js, saf)

### Yardımcı: `bnsBaselineCycle(completed, key, keyField)`
Bir kategorinin (departman veya marka) geçmiş **medyan tamamlanma döngüsü** (saat).
- `completed`: tamamlanan brief'ler (`sureH`, `dept`/`marka` alanlı).
- `keyField`: 'dept' | 'marka'. `key`: eşleşecek değer.
- Eşleşen brief'lerin `sureH` medyanı; **en az 3 örnek yoksa** `null` (güvenilmez baseline).
- Dönüş: `number | null`.

### 1. `bnsGecikmeOngoru(b, baselineH, now)`
Aktif brief için gecikme riski (davranışsal + geçmiş döngü birleşik).
- Girdi: `b` = { deadline, durum, rev_ic, rev_musteri, elapsedH } (elapsedH çağıran tarafça bnsCycleSure ile hesaplanır), `baselineH` (null olabilir), `now`.
- `timeLeftH = (b.deadline - now) / BNS_H`.
- **projMiss** (baseline varsa): `(baselineH - b.elapsedH) > timeLeftH` — kalan beklenen iş, kalan zamana sığmıyor.
- **behavioral**: `(b.rev_ic + b.rev_musteri) >= 2 && ['yeni','calisiliyor','revizyon'].includes(b.durum) && timeLeftH < 48`.
- Zaten teslim/müşteride/tamamlanmışsa (`['incelemede','musteride','tamamlandi'].includes(b.durum)`) → risk yok.
- Dönüş: `{ risk: bool, sebep: 'projeksiyon'|'davranissal'|null }`.

### 2. `bnsBurnout(upcomingCount, capLimit)`
Kişinin gelecek-5-gün doluluk projeksiyonu.
- `projPct = capLimit > 0 ? Math.round(upcomingCount / capLimit * 100) : 0`.
- Dönüş: `{ pct, asiri: projPct >= 120 }`.

### 3. `bnsKisiPerformans(completed, now)`
Kişinin tamamlanan işlerinden metrik demeti.
- Girdi: `completed` = o kişinin tamamlanan brief'leri ({ sureH, deadline, bitis, rev_ic, rev_musteri, rating, marka, dept }).
- Dönüş:
  ```
  { tamamlanan,            // sayı
    ortDonguH,             // ort. sureH (round .1)
    zamanindaPct,          // bitis <= deadline olan % (deadline'ı olanlar üzerinden)
    ortRevize,             // ort. (rev_ic + rev_musteri) (round .1)
    ortPuan,               // ort. rating (round .1, null-safe)
    tipDagilim,            // { marka veya dept: sayı }
    throughputHaftalik }   // son 4 haftada iş/hafta (round .1)
  ```
- Boş girdide sıfır/null güvenli döner.

### Sinyal sarmalayıcılar (firma-sinyal.js motoru için)
- `bnsSinyalGecikme(atRiskBriefs)` — her at-risk brief için `{ tip:'gecikme_ongoru', aciliyet:'acil', key:marka, text }`. (Çağıran, bnsGecikmeOngoru ile filtreler.)
- `bnsSinyalBurnout(kisiler)` — her aşırı-yüklü kişi için `{ tip:'burnout', aciliyet:'normal', key:ad, text }`.

## firma-sinyal.js entegrasyonu

`sinyalleriHesapla` içine eklenir:
- **Gecikme öngörüsü:** her aktif brief için baseline (dept, yoksa marka, ikisi de <3 örnek ise atla) + elapsedH (bnsCycleSure(b.durum_olaylari, now)) → bnsGecikmeOngoru → at-risk olanlardan bnsSinyalGecikme.
- **Burnout:** kişi başına gelecek-5-gün (deadline ∈ [now, now+5g]) aktif iş sayısı + capLimit → bnsBurnout → aşırı olanlardan bnsSinyalBurnout.

Baseline ve elapsedH embedded'dan; `bns_completed` (baseline) ve `bns_briefs[].durum_olaylari` (elapsedH) mevcut.

## Dashboard rozeti

At-risk aktif brief'lerde "⏳ öngörülen gecikme" rozeti. Mevcut risk rozetinin (bnsIsRisk) yanına, aynı bileşende. Görünürlük: atanan (worker/lead) veya yönetici. Baseline client-side `bnsBaselineCycle(d.bns_completed, ...)` ile, elapsedH `bnsCycleSure` ile hesaplanır. Yerleşim: İşler/Jobs listesi satırı ve/veya BriefDrawer (mevcut risk rozetinin olduğu yer).

## Veri / hata / test

- **Veri:** embedded (bns_briefs.durum_olaylari, bns_completed.sureH/rating/rev, deadline). Migration yok.
- **Hata:** baseline <3 örnek → null → yalnız davranışsal sinyal çalışır (projeksiyon atlanır). LLM yok.
- **Test (formula-test.js):**
  - `bnsBaselineCycle`: 3+ örnek medyan; <3 → null.
  - `bnsGecikmeOngoru`: projMiss sınırı; behavioral (revize≥2 + erken durum + <48h); teslim edilmiş durum → risk yok.
  - `bnsBurnout`: %119→asiri false, %120→true.
  - `bnsKisiPerformans`: zamanında %, ort revize/puan/döngü, boş girdi.
  - `bnsSinyalGecikme`/`bnsSinyalBurnout`: sinyal sayısı + key.
