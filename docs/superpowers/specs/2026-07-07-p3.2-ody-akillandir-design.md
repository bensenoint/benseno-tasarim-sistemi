# P3.2 — Ody'yi Akıllandır — Tasarım Spec'i

> Tarih: 2026-07-07 · Faz: P3.2 (fırsat haritası) · EFOR: M · Altyapı: mevcut veri (+1 kolon) · Risk: orta (ton/risk yanlış-etiket → muhafazakâr eşik)

## Problem

Ody topladığı en pahalı sinyalleri kullanmıyor: (1) `ody_advice_feedback` (beğen/beğenme + sebep + sonuç) hiçbir okuma yolunda yok → öğrenmiyor; (2) `brand_daily` gün-sonu insight'ları her gün LLM ile üretiliyor ama sadece metin kutusunda → müşteri-risk trendine dönmüyor; (3) thread özetleri nötr → gerilim/memnuniyetsizlik tonu görünmüyor.

## Kullanıcı kararları (onaylı)

- P3.2 = **Ody'nin zekasını ZENGİNLEŞTİRME** (öğrenme + müşteri/ton bağlamı). **Proaktif yöneticiye push P3.3'e ertelendi** — bu fazda yalnız sorulunca (Ody tool) + dashboard rozeti.
- Üç parça birlikte: V1 (feedback döngüsü), V7 (müşteri-risk trendi), V9 (thread duygu tonu).
- Ton/risk yönetici-only (mevcut S2 gizlilik kalıbı).

## V1 — Feedback öğrenme döngüsü

- **Veri:** `ody_advice_feedback` (mevcut: vote up/down, reason, outcome kept/revised, advice_text).
- **Mekanizma (cron YOK, canlı okuma):** Prompt kurulurken hem `/api/chat` (server/api.js) hem `scripts/ody-icgoru.js`:
  - `SELECT advice_text, reason FROM ody_advice_feedback WHERE vote='down' ORDER BY created_at DESC LIMIT 20`
  - Bunlardan kısa bir "kaçınılacaklar" özeti üretilip sistem promptuna eklenir:
    *"GEÇMİŞ GERİ BİLDİRİM — kullanıcılar şu tarz önerileri beğenmedi (tekrarlama): [reason/advice kısa liste]."*
- **Saf yardımcı (test):** `bnsFeedbackOzet(rows)` → downvote sebeplerini derleyip ≤400 karakter tek bloğa indirir (boşsa boş string). server/ody-tools veya küçük util'de.
- **Sonuç:** Ody tekrar eden kötü önerilerden kaçınır; ölü tablo dirilir.

## V7 — Müşteri-risk trendi (marka sağlığı)

- **Veri:** `brand_daily` (kanal-ozet.js gün-sonu insight arşivi; marka + gün + insight metni).
- **Mekanizma:** Yeni Ody tool `marka_risk` (yönetici-only):
  - Son ~5 günün `brand_daily` insight'ını LLM'e ver → **risk_seviye** (dusuk/orta/yuksek) + tek cümle gerekçe.
  - Sonuç `brand_daily.risk_seviye` (migration) veya küçük cache'e yazılır (aynı gün tekrar hesaplamasın).
- **Dashboard:** Marka detayında yönetici rozeti (🟢/🟡/🔴 + gerekçe).
- **Erişim:** yönetici-only. **Proaktif DM YOK (P3.3).**
- **Risk yönetimi:** düşük örneklem (az günlük insight) → "yetersiz veri" döner, yüksek-risk uydurmaz.

## V9 — Thread duygu tonu

- **Mekanizma:** `scripts/thread-ozet.js` zaten thread'i LLM'le özetliyor — **aynı çağrıya `ton` alanı** ekle (enum: notr|gergin|memnun|acil; muhafazakâr — emin değilse notr).
- **Migration 0014:** `briefs.thread_ton TEXT`.
- **Yüzey:** `is_detay` Ody tool'una `ton` alanı + BriefDrawer'da yönetici rozeti (🙂/😐/😟/🔥).
- **Erişim:** ton yönetici-only.
- **Maliyet:** ~sıfır ek (mevcut çağrıya alan).

## Ortak

- **Migration 0014:** `ALTER TABLE briefs ADD COLUMN IF NOT EXISTS thread_ton TEXT;` + `ALTER TABLE brand_daily ADD COLUMN IF NOT EXISTS risk_seviye TEXT;` (brand_daily varsa; yoksa V7 cache ayrı tabloya).
- **Erişim:** ton/risk yönetici-only (ody-tools'ta `ctx.isAdmin || rol='yonetici'`; dashboard `_isMgr`).
- **Tek kaynak:** feedback-özet + risk-sınıf saf mantığı test edilir.

## Kapsam dışı (sonraya / P3.3)
- Marka-risk / ton yükselişinde **proaktif yönetici DM'i** → P3.3.
- Feedback'ten otomatik prompt A/B / ince ayar → ileride.
- Geçmiş thread'lere toplu ton doldurma (backfill) — yeni özetlerde dolacak; istenirse ayrı script.

## Test
- **Birim:** `bnsFeedbackOzet` (downvote derleme, boş, 400-kırpma); `marka_risk` girdi biçimi + düşük-örneklem "yetersiz veri"; ton parse (geçersiz → notr).
- **CI** + mevcut testler regresyonsuz.
- **Migration 0014** idempotent.
- **Prod dry:** Ody yöneticiye `marka_risk` döner, düz üyeye "yöneticilere özel"; feedback bloğu prompt'a giriyor (downvote varsa); yeni tamamlanan işte thread_ton doluyor.
