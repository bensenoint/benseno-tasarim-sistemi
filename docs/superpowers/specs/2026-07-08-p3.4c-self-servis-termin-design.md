# P3.4c — Self-Servis Termin/Hatırlat (Tasarım)

**Tarih:** 2026-07-08
**Faz:** P3.4 Çalışan şeffaflığı → alt-faz **c** (son). **Fırsat haritası:** Ç6 — "Düz tasarımcı kendi terminini uzatamaz/hatırlatamaz → her şey lead'e bağımlı."

---

## Amaç

Atanan (worker) kişi **kendi atandığı** işte "Termini uzat" ve "Hatırlat" aksiyonlarını kullanabilir. Lead'e bağımlılık kalkar; öz-çerklik artar.

## Mevcut durum (keşif)

| Aksiyon | UI (`bnsBriefActionPerms`) | Server |
|---|---|---|
| Termini uzat | `termin_oneri_ms && (lead ∨ açan ∨ yönetici)` | rol kontrolü YOK (writeGuard auth) — gate UI-only |
| Hatırlat | `lead ∨ yönetici` | `lead ∨ açan ∨ yönetici` (403) + 10dk dedup |

Not: Hatırlat'ta UI↔server tutarsız (server `açan`a izin verir, UI vermez) — bu faz giderir.

## Değişiklik

1. **calc.js `bnsBriefActionPerms`:**
   - `out.termin = !!b.termin_oneri_ms && (isAssignee || isCreator || isMgr);` (isAssignee = lead∨worker; `termin_oneri_ms` ön-koşulu KORUNUR)
   - `out.hatirlat = isAssignee || isCreator || isMgr;`
2. **server/api.js `/api/briefs/:id/remind`:** lead sorgusundan `AND role='lead'` kalkar → herhangi bir `brief_assignees` kaydı (lead veya contributor) yeterli. Yönetici/açan yolu ve **10dk spam koruması aynen kalır**.
3. **Termin uzat server'ı:** değişiklik yok.

## Kapsam dışı

- Yeni UI ögesi yok — mevcut butonlar perms'e bağlı, kural gevşeyince kendiliğinden görünür.
- Uzatma miktarı/limiti değişmez (`applyTerminOneri` mantığı aynen).
- Migration yok.

## Güvenlik / kötüye kullanım freni

- Hatırlat: 10dk/iş dedup korunur (spam freni).
- Termin uzat: yalnız `termin_oneri_ms` set edilmişse (bekleme/müşteride dönüşü önerisi) — keyfi uzatma yolu açılmaz; `uzatma_sayisi`/ceza mekanizması (bnsUzatmaCeza) aynen işler, yani kişi kendi puan cezasını göze alarak uzatır (öz-denge).
- Atanmamış kişi: UI'da buton görünmez; hatırlat server 403 verir; termin server'ı rol kontrolü yapmıyordu (mevcut durum, değişmiyor).

## Test

- formula-test `bnsBriefActionPerms`:
  - worker + öneri var → `termin true`
  - worker, öneri yok → `termin false`
  - worker → `hatirlat true`
  - açan (atanmamış) → `hatirlat true` (tutarsızlık giderme)
  - atanmamış/açan-değil/yönetici-değil → ikisi de `false`
- Server: kod incelemesi + `node --check` (endpoint test altyapısı yok — mevcut desen).

## Deploy

API (server/api.js) + dashboard (calc → bundle). Doğrulama: health 200, CI, canlıda buton görünürlüğü kullanıcı onayıyla.

## Başarı ölçütü

Worker kendi işinde termin-uzat (öneri varken) ve hatırlat butonlarını görür/kullanır; atanmamış kişi göremez (hatırlat 403); testler + CI geçer; iki servis deploy.
